# Demo script

Use a dedicated Omarchy VM or clean workspace with fictional data. Start in Neon
Glow. Record the screen, desktop output, and microphone; O.M.A. supports shared
microphone capture with recording software.

## Short introduction

1. Say “Hey O.M.A.” and wait for “Awaiting your command.”
2. “What are you?”
3. “Change the theme to Tokyo Night.”
4. “Thanks. Bye!”

## Extended desktop demo

- “Show me this machine's specs with fastfetch.” Keep the terminal visible.
- “Write a digital clock plugin in Neovim.” Show code appearing in the actual
  editor buffer, not a completed file opened afterward.
- “Open ten windows showing the Omarchy logo.” Use separate tiled windows.
- “Change the theme to Tokyo Night.” Show the wallpaper, bar, and terminal colors.

Let each task finish before the next instruction. Assistant replies should be
actual generated responses, not prerecorded promises of success. Use normal
speed for the visible coding sequence; label edited waiting time explicitly.

## Recording checklist

- Verify microphone routing, wake detection, playback, and readability first.
- Use a VM snapshot for repeatable starting conditions. VM specifications must
  not be presented as the physical host's specifications.
- Remove unrelated notifications and private windows before capture.
- Keep terminal usernames, hostnames, and file contents suitable for publication.
- Disclose synthesized user commands, reenactments, or supplementary shots.
- Do not present keyboard-triggered commands as voice recognition.
- Show real approval prompts if they occur; do not imply unconditional autonomy.
- Restore Neon Glow between takes. Change only the demo environment.
- Keep narration and O.M.A.'s output on separate tracks when possible.
